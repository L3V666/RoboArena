# RoboArena

**RoboArena** — 2D-игра на C++17 и SFML. Игрок управляет роботом на арене, стреляет по врагам и переживает несколько волн противников. Враги строят путь до игрока по клеточной карте с помощью A*.

## Возможности текущей версии

- окно SFML и игровой цикл;
- карта-арена на сетке;
- движение игрока с коллизиями;
- базовая система сущностей `Entity`;
- хранение сущностей через `std::vector<std::unique_ptr<Entity>>`;
- шаблонное создание сущностей через `EntityManager::create<T>()`;
- шаблонный поиск сущностей через `EntityManager::getAll<T>()`;
- базовый класс `Enemy` и наследник `ChaserEnemy`;
- A* pathfinding для врагов;
- снаряды игрока;
- отдельная `CombatSystem`;
- здоровье игрока и врагов;
- удаление уничтоженных сущностей;
- волны врагов через `WaveSystem`;
- победа после прохождения всех волн;
- перезапуск игры клавишей `R`;
- HUD с полосой здоровья, прогрессом волны и перезарядкой выстрела.

## Управление

```text
WASD / стрелки — движение
ЛКМ — выстрел
R — перезапуск
Esc — выход
```

## Сборка

Требования:

- C++17;
- CMake 3.16+;
- SFML 2.5+.

```bash
mkdir build
cd build
cmake ..
cmake --build .
./RoboArena
```

## Основные модули

### `core`

Содержит класс `Game`, который управляет главным циклом, событиями, обновлением состояния и отрисовкой.

### `entities`

Содержит игровые сущности:

- `Entity`;
- `Player`;
- `Enemy`;
- `ChaserEnemy`;
- `Projectile`.

Наследование используется осмысленно: у игровых объектов есть общий интерфейс `update()`, `draw()`, `getBounds()`, но поведение разное.

### `systems`

Содержит независимые системы:

- `EntityManager`;
- `Pathfinder`;
- `CombatSystem`;
- `WaveSystem`.

`WaveSystem` отвечает за порядок волн, интервалы спавна и проверку победы.

### `map`

Содержит клеточную карту `GridMap`. Карта хранится как вложенный контейнер:

```cpp
std::vector<std::vector<Tile>> tiles_;
```

## Алгоритмы

Враги используют A* для поиска пути по карте. Клетки карты рассматриваются как вершины графа, а переходы между соседними проходимыми клетками — как рёбра.

В реализации используются:

- `std::priority_queue` для frontier;
- `std::unordered_map` для стоимости пути и восстановления маршрута;
- `std::vector` для хранения итогового пути.

## STL и оптимизация

В проекте используются:

- `std::vector`;
- `std::vector<std::vector<Tile>>`;
- `std::unique_ptr`;
- `std::make_unique`;
- `std::move`;
- `std::priority_queue`;
- `std::unordered_map`;
- `std::remove_if`;
- range-based `for`.

`std::vector` выбран для хранения сущностей и карты из-за хорошей кэш-локальности. Удаление уничтоженных объектов выполняется через erase-remove idiom.

## Стиль кода

В проекте используются:

- разбиение на `.hpp` и `.cpp`;

- `final`;
